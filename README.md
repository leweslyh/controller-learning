## V5.1 P0 修复

本轮依据《控制理论模拟器 V5.0 技术审查与优化报告》，只修复会直接误导教学结论的 4 项 P0 缺陷，并同步更新帮助、文案与验收；159 条控制律本身未改写。

### 1. 倒立摆不再忽略外扰与摩擦（E-01）

倒立摆分支改为复用对象声明的 `plant.accel()`，`ext_f`（恒值风扰 + 脉冲扰动）与库仑摩擦正式进入摆角方程。实测（PID，初值 0.15 rad，24 s）：

| 条件 | 最大摆角 |
|---|---|
| 无扰动 | 0.13565 rad |
| 脉冲扰动 | 0.32452 rad |
| 恒值扰动 30 N·m | 0.15287 rad |

修复前三种条件完全相同（0.14527 rad），“扰动”按钮在倒立摆上是无效控件。关闭辅助（真实动力学）时对应为 0.14787 / 0.60860 / 0.86525 rad。

### 2. 摆平衡辅助改为显式辅助控制器（E-02）

原来的隐藏 PD 写在对象方程内部、且增益随控制量 `|F|` 变化，等于把被控对象替换成了一个依赖控制器的模型。现在改为：

- 独立的 **辅助 PI 控制器**（比例 + 积分，固定增益，不随 `|F|` 变化）；
- 与主控制律**共用同一执行器**：先相加，再统一过限幅、死区、纯滞后；
- 关闭后回到纯真实不稳定动力学；
- 帮助面板与参数下拉文案明确说明其存在与作用。

因此“教学稳定模式下 159/159 方法稳摆”仍然成立，但它来自一个显式、可解释的辅助控制器，而不是被篡改的对象。关闭辅助后（真实动力学）实测 **144/159 good、6 fair、3 poor、6 unfit**；6 个发散项为 IMC、SmithPredict、TubeMPC、MAC-Impulse 等内模/预测类方法（结构上与负刚度对象不兼容），以及 OpenLoop、Relay 两个方法本质例外，不再是隐藏 PD 掩盖的假象。

### 3. 一键最优增益增加可行性与退化守卫（E-03）

- 新增 30 s 长轨迹复核：以末段 2 s 的均值误差与标准差判定是否真正收敛，避免短视界把持续振荡误判为“最优”；
- 拒绝退化解：全部参数为 0、关键比例增益为 0、积分增益为 0（会让 PI/PID 退化）均判为不可行；
- 不可行时**不写回参数**，提示“未找到满足收敛要求的增益，建议更换方法或对象”；
- 求解前保存快照，新增「撤销求解」按钮与 `Ctrl+Z`；
- toast 改为回报可观测指标（末段误差、超调），不再只报内部代价百分比。

实测：`二阶积分器 + P` 不再写回 `Kp=0`（Kp 保持 34，提示不可达）；`飞机 + Repetitive` 求解后出现撤销按钮，撤销后 `k_rc` 由 0.1 恢复为 5.0。

### 4. 负刚度对象增加 Routh 稳定下限（E-04）

全局覆盖表 `DEFAULT_OVERRIDES` 中按弹簧负载整定的低增益，会把 `k<0` 的对象直接推入不稳定区。现在在对象感知整定之后增加硬下限：

```
Kp ≥ -k + 2.0 · m · |Ki| / (c + Kd)
```

实测：导弹 + PI 默认参数由 `Kp=3, Ki=0.5`（末段误差 −2.63 rad，发散）修正为 `Kp=5, Ki=0.5`（末段误差 −0.0021 rad）；倒立摆 + PI 在真实动力学下由发散修正为收敛。

## V5.3 教学一致性修订

本轮针对实际试看中发现的问题做六项修正，不改变任何控制律与物理方程。

1. **两个四旋翼统一画法**：高度通道原来自绘了一套侧视机体，和滚转通道的正面机体不是同一架飞机。现改为共用 `glyphUav`，只做垂直平移——同机同形，差别只在自由度。
2. **下垂单摆的弧线与箭头**：角度弧原按 `a1<a0` 选逆时针方向，小角度时会绕远路画出接近整圈的大圆弧；改为固定走短弧，弧半径收到 58 px 以内。力矩指示改为固定半径的小弧 + 切向箭头（`arcHead`），不再随摆长放大成"大圆弧"。对象用途在手册与讲解中明确：它是**稳定、极轻阻尼**的振动抑制基准，也是倒立摆的镜像对照（$k$ 符号相反）。
3. **对象手册覆盖全部 11 个对象，方法文档不再复制对象总表**：新增 `msd / freeMass / pendulum / aircraft / missile / uav` 六篇手册（各 8～9 章，含极点、阻尼比、直流增益、保持力、实测评级与差评原因）；159 篇方法文档第 2 章删除共用的"六个对象"表，只保留本方法使用的「质量-弹簧-阻尼」，并链到对象手册。新增 `tools/normalize-doc-plants.js` 可重复执行。

## V5.0 本轮改动（Netlify 前后端分离）

V5.0 的部署架构轮次只做部署与鲁棒性改造，前端交互、159 法文档、公式与仿真结果保持不变（后续功能回灌见下一节）：

- **后端函数置于 `netlify/functions/` 顶层（关键修复）**：原 `netlify/functions/api/chat.js` 这种嵌套两层布局 Netlify 不识别——它只认 `functions/<name>.js`、`functions/<name>/<name>.js`、`functions/<name>/index.js` 三种模式，嵌套两层会让函数整体不被打包、`/api/*` 全 404。V5.0 已改为 `netlify/functions/chat.js` 等顶层文件，路由仍由 `config.path` 挂到 `/api/*`。
- **删除与 `config.path` 冲突的 rewrite**：三个函数都用 Functions 2.0 的 `export const config = { path: '/api/…' }` 声明路由；V4.0 的 `[[redirects]] /api/* → /.netlify/functions/:splat` 会把请求重写到函数并未注册的默认路径，导致即使部署成功也 404，V5.0 已移除。
- **`auto` 模式增加回落**：同源 `/api/chat` 缺失或报错且尚未输出时，自动回落浏览器直连；`file://` 直开仍只走直连。配合 404 专用提示，线上函数没上线时不再无声降级为离线检索。
- **超时对齐平台上限**：Netlify Functions 同步执行上限 60s，上游流式超时取 55s，前端等待上限同步改 55s（原 120s / 90s 会被平台提前掐断）。
- **`public/_headers` 补 `/api/*` no-store**：不依赖 `netlify.toml` 的 headers 段，手动部署同样生效。
- **双平台后端并存**：`netlify/functions/` 为 Netlify Functions 2.0 版（`netlify.toml` 生效目录）；`functions/api/` 为功能等价的 Cloudflare Pages Functions 备选版（按文件路径映射 `/api/*`），两者逻辑同步维护，部署时二选一。

## 1.1 智能助手

**界面**：顶部菜单栏「智能助手」按钮或按 `A` 打开；拖动标题栏移动窗口（也可用方向键微调），位置会记住；快捷提问条覆盖「关键公式 / 参数怎么调 / 方法对比 / 常见误区」；回答下方来源按钮可直接打开对应教学文档；设置面板可改同源接口路径、编辑长期记忆、清空记忆。

**流式输出**：以 `stream: true` 请求 DeepSeek SSE；前端用 `ReadableStream` 按事件解析并约 70ms 合并一次渲染，流式期间用轻量文本、结束后统一排版 Markdown/KaTeX；思考模式先显示「思考中…」，中途点「终止」会保留已收到内容；同源代理与本地服务均逐块透传，不缓冲成一次性文本。

**知识库 / RAG**：语料就是本目录的 `public/docs/methods/*.md`，运行 `node tools/build-docs.js` 打包为 `public/js/docs-content.js`（`window.__DOCS__`）。`public/js/assistant.js` 按 `##` 章节切块，构建中文 bigram + 英文词的词频索引，用 BM25 打分，叠加标题/分类命中与「当前方法」加权，取 Top-5 片段注入提示词；文档更新后重跑打包脚本即可。

**记忆**：`ctrlsim.v4.assistant`（localStorage）保存最近 12 条对话、用户显式事实、近期关注的方法与窗口位置；每次请求携带最近 8 条对话 + 长期事实 + 关注方法 + 当前实验方法。

**接入 DeepSeek**：

```powershell
$env:DEEPSEEK_API_KEY="sk-..."; node tools/assistant-server.mjs
# 打开 http://localhost:8713
```

**部署到 Netlify（前后端分离）**：

- 前端 `public/` 为 publish 目录；后端 `netlify/functions/` 为函数目录（Netlify 默认路径，无需在 UI 额外指定）。
- 推荐 **Git 连动部署**：仓库根目录就是本项目，Netlify 读取 `netlify.toml` 的 `publish = "public"`、`functions = "netlify/functions"`，每次 `git push` 自动重建。
- 也可用 CLI 手动部署并显式带函数：`npx netlify-cli deploy --prod --dir=public --functions=netlify/functions`。
- **不要**用「拖拽 / Deploy manually」只上传 `public/`：那不会打包函数，`/api/chat` 会 404。
- 部署后在站点环境变量设置 `DEEPSEEK_API_KEY`（可选），再访问 `/api/health` 确认返回 JSON。
- 未设置密钥或请求失败时，助手自动降级为纯本地文档摘录，不影响任何仿真功能。

**安全**：API Key 只在服务端环境变量读取，`public/` 不含密钥；`/api/chat` 默认无鉴权，公开部署时请在平台侧补上访问控制或速率限制。对话与记忆只存本机浏览器，提问与检索片段会发送给你配置的模型服务。

## 3. 纸面实验室设计语言（取自 liziwuli.com）

界面视觉不是「风格印象式仿制」，而是直接对齐「粒子先生的物理实验室」站点的实际样式表令牌：

| 令牌 | 取值 | 站点来源 |
|---|---|---|
| `--paper` | `#f7f2e8` | 页面纸底 |
| `--panel` / `--panel-raised` | `#fffaf1` / `#fffdf8` | 卡片面 / 抬升面 |
| `--ink` = `--frame-line` | `#151715` | 墨色，同时是边框色 |
| `--shadow-hard` | `3px 3px 0 #151715` | 实心硬投影（无模糊） |
| `--green` / `--green-soft` | `#2f8f55` / `#eaf5ea` | 主强调 / 强调底 |
| `--red` `--blue` `--orange` `--purple` | `#b65249` `#2f6fb3` `#d2742c` `#8057a8` | 语义色板 |
| 圆角档位 | `4 / 5 / 6 / 8 / 999` | 站点 radius 变量 |
| 边框档位 | `1 / 1.5 / 2 / 3px` | 站点 border 变量 |
| 字体 | HarmonyOS Sans SC → PingFang SC；数学 Times New Roman | 站点 `--font-body` / `--font-math` |
| 指针 | 自定义 SVG 箭头（白底 + 墨描边，指针态换绿底） | 站点 `--cursor-default` / `--cursor-pointer` |

落到本项目的具体做法：

- **纸面主体**：`body` 用米纸底 + 28px 极淡网格，顶栏与状态栏用 2px 墨线夹住，品牌标志是 3px 墨边直角方块 + 绿色 soft 底 + 版本 pill（2px 墨边、5px 圆角）。
- **章节即导航**：左栏 12 类体系做成参考站点式的「章节卡」——中文数字编号（一…十二）+ 标题 + 方法数 + 折叠箭头；展开项编号反白为绿底，未展开时为绿字浅底。教学文档阅读器目录沿用同一编号体系。
- **层次靠边框粗细与投影区分**：主舞台与被控对象/图表面板用 2px 墨边 + 3px 硬投影；左右栏、指标卡、参数小卡只用 1.5px 柔和线 + 纸面柔光，避免满屏硬边造成噪音。
- **交互元件统一胶囊**：按钮、搜索框、速度滑块、分段 tab、标签全部 999px 圆角 + 2px 墨边 + 2px 硬投影，`:active` 时位移 2px 并收掉投影，模拟纸片被按下。速度滑块采用**对数刻度**：前半程对应 0.1×~1×，后半程 1×~10×，低倍速可精细调节；点击「仿真速度」标签可一键恢复默认 1×。
- **概览条**：左栏顶部 159 / 12 / 6 三格对应站点首屏的「12 学习模块 · 90 个互动实验」亮点条。
- **夜间实验室**：`[data-theme="dark"]` 沿用站点深色令牌——纸 `#13171c`、面 `#232a33`、墨 `#eaece8`、绿 `#46b576`，硬投影换成 `#090c0f`。
- **图表跟随换肤**：canvas 通过 `getComputedStyle` 读取 `--surface-3 / --divider / --curve-*`，切换主题时曲线、网格与坐标轴同步换色，无需重启仿真。

**左栏挂起规则**

## 4. 经典被控对象与姿态通道

本轮聚焦到控制理论最经典的三个对象，其余四个（一阶惯性、直流电机、Duffing 振子、液位水箱）已从数据层与绘制层一并移除，避免「每个都浅」——159 种算法照旧可用。另有三个**二维单通道姿态对象**（飞机俯仰 / 导弹俯仰 / 无人机滚转）见 4.1 节，它们与三个经典对象共用同一套控制律与指标。

| 对象 | 方程（控制输入 u 的定义） | 动画画面 |
|---|---|---|
| 二阶积分器（默认） | $m\ddot x=u$，u 为**作用在质量块上的水平力**，纯二阶积分、无一阶项、无回复力 | 无弹簧小车 + 轨道 + 目标虚线 |
| 质量-弹簧-阻尼 | $m\ddot x+c\dot x+kx=u$，u 为**作用在质量块上的水平力** | 左墙 + 弹簧 + 阻尼器 + 质量块 + 力箭头 |
| 倒立摆（小车-摆） | $\ddot\theta=\frac{(M+m)g}{Ml}\theta-\frac{c}{Ml}\dot\theta+\frac{1}{Ml}u$，u 为**作用在小车上的水平推力 F**（不是摆轴力矩） | 导轨 + 小车与双轮 + 铰接摆杆 + 摆球 + θ 角弧 + 推力箭头 |

**默认对象 = 最简单的二阶积分器** $m\ddot{x}=u$：只有一个质量参数，没有阻尼项（一阶项）、没有弹簧回复力。它是控制理论最干净的二阶基准，但代价是**它自己站不住**——纯比例控制的闭环特征方程 $m\,s^{2}+K_p=0$ 没有阻尼极点，只能等幅振荡；PI 违反 Routh 判据必然发散；开关/继电类只有极限环。这是数学上的硬限制而非实现缺陷，因此**默认对象的适用性徽章如实标注**「请切到质量-弹簧-阻尼对象体验 P / PI 的静差与整定」。

**教学文档用模型 = 最简单的质量-弹簧-阻尼** $m\ddot{y}+c\dot{y}+k\,y=u$：理想化，不含执行器时延与库仑摩擦（实验台上的同名对象另外叠加了时延与外扰机制）。选它而不是二阶积分器，是因为第 3 章要用**当前参数实时求闭环极点**：二阶积分器上 P / PI 的特征方程无阻尼极点或直接发散，数值算例会失真；二阶质量-弹簧-阻尼既有回复力（$k>0$）又有阻尼（$c>0$），极点数值良态，最适合逐章推导与对照。

为保证「159 种方法在默认对象上能真正达成控制目标」，`PLANT_TUNING.freeMass` 收录了逐方法搜索得到的默认增益（由 `tools/audit-plant.js` 搜出）：默认参数下 **159×3 组合中 good 400 / fair 45 / poor 11 / unfit 21（适用率 93.3%）**（末段位置误差 < 0.05）。未达 good 的是开环对照基准、开关/继电极限环与学习/混沌演示级算法，另有 **P / PI / BangBang / Relay 四类在纯二阶积分器上数学上不可收敛**（见上），逐条说明见 `docs/方法适配审计.md`。

倒立摆采用标准的小车-摆模型：摇摆方程由小车平动方程与摆杆转动方程联立消元得到，θ 从竖直向上量起、**向左倾为正**，因此正推力对应 θ̈ 为正（推右→摆左倾），符号与物理解释自洽。默认 `M=1.0 kg, m=0.2 kg, l=0.8 m, c=0.05`，等效 `k=−(M+m)g` 为负 → 开环不稳定，默认初始偏角 0.15 rad。

主舞台不再常驻公式条（V4 的 `.eqbar` 已在 V5 移除，舞台更简洁）：动力学方程集中在按需打开的**对象模型弹窗**（「方程与符号」按钮或快捷键 `M`），分节讲清楚：① 物理含义 ② 符号 / 名称 / 当前值 / 单位 / 可调范围表 ③ 等效二阶形式与 m·c·k 当前值 ④ 控制输入施加在哪（尤其区分倒立摆的「小车水平推力」与「摆轴力矩」）⑤ 对象专属进阶讲解（倒立摆串级 / 姿态通道）。每个对象通过 `effective(p)` 提供等效 `m/c/k`，供 159 条控制律共用；倒立摆取 `m=Ml, k=−(M+m)g`，与 `accel()` 完全一致（非近似）。

**默认参数整定（V5.1）**：**全部对象**统一接入 `getTheoreticalOptimalSeed`——切换对象或方法时，按当前等效 `m/c/k` 与运行环境为 159 种方法逐个推导「理论最优默认参数」，由 `applyTuning()` 自动套用；应用顺序为 `理论种子 → DEFAULT_OVERRIDES → PLANT_TUNING`，最后对 `k<0` 的对象施加 Routh 稳定下限 `Kp ≥ -k + 2.0·m·|Ki|/(c+Kd)`。显式 `PLANT_TUNING` 仍具有最高优先级。

- **质量-弹簧-阻尼**：默认阻尼 `c` 由 0.5 提到 1.5，并为 P / PI / OpenLoop 补专属调参（`kp=100` / `kp=40,ki=5` / `u_static=5`），使这三种原本因欠阻尼或开环而长期振荡 / 停不到目标的方法也能视觉收敛（P 的约 1% 静差是物理必然）。V5.1 实测 147/159 good；剩余 `Relay`（继电极限环）、`Repetitive`（需周期目标）、`Lorenz-Coupled`（混沌）属于方法本质特性，非参数可修。
- **倒立摆**：新增「摆平衡辅助」开关（参数栏「小车位置闭环（进阶）」分组，默认**开启**）。V5.1 起它是一个**显式辅助 PI 控制器**（固定增益，与主控制器共用执行器，先相加再过限幅/死区/滞后），不再写进对象方程、也不随 `|F|` 变化；因此外扰、饱和、死区对辅助同样生效。开启时 159 种方法（含 P / PI / 开环）都能稳住摆，实测 **159/159 good**；关闭后回到真实不稳定拉格朗日动力学，实测 **144 good / 6 fair / 3 poor / 6 unfit**，6 个发散项集中在与负刚度对象结构不兼容的内模/预测类方法与 OpenLoop/Relay。小车设软回中与 ±8 m 软边界避免漂出画面。

### 4.1 姿态控制通道（飞机 / 导弹 / 无人机，二维单通道）

三个飞行器对象只保留**绕机体一根轴的转动自由度**，把三维姿态问题降维成可直接对照教材的 SISO 回路：

$$J\ddot\theta + c\dot\theta + k\theta = M$$

| 项 | 含义 | 量纲 |
|---|---|---|
| $J$ | 绕该轴的转动惯量（等效 `m`） | kg·m² |
| $c$ | 气动阻尼力矩系数 | N·m·s/rad |
| $k$ | 静稳定力矩系数 | N·m/rad |
| $M$ | 控制器给出的**控制力矩**（等效 `u`） | N·m |

方程与 `mẍ + cẋ + kx = u` 完全同构，所以 **159 条控制律一行都没改**，只靠 `effective()` 把 `J/c/k` 映射到 `m/c/k`。三者用 `k` 的符号区分「脾气」，这是姿态教学的主线：

| 对象 | 方程 | 参数默认 | `k` 的物理含义 | 教学用途 |
|---|---|---|---|---|
| 飞机（俯仰姿态） | $J\ddot\theta+c\dot\theta+k\theta=M,\ k>0$ | $J=2.5,\ c=2.2,\ k=4$ | 气流把机头吹回来流方向，**静稳定** | 气动阻尼、配平力矩、P 控制的静差 |
| 导弹（俯仰姿态） | 同式，$k<0$ | $J=1.2,\ c=0.4,\ k=-2$ | 气动中心在重心之前，**静不稳定**，开环极点 $+\sqrt{|k|/J}$ 落在右半平面 | 反馈为何是必需品；极点配置/滑模镇定 |
| 无人机（滚转姿态） | $J\ddot\phi+c\dot\phi=M,\ k=0$ | $J=0.8,\ c=0.35$ | 无气动回中力矩，本质是带阻尼的双积分器 | 电子阻尼，D 项（角速率环）的必要性 |

实现要点：

- **数据层**：`PLANTS.aircraft / missile / uav`（`data.js`），字段与三个老对象同构——`order:2` + `accel()` + `effective()` + `holdForce()` + `restoring()`，另加 `disturbanceScale`（脉冲扰动量级按 rad 量纲折算）与 `teaching`（对象弹窗第五节的专属讲解，由 `ui.js` 数据驱动渲染）。
- **仿真层**：`simulation.js` 无需特判——`order===2` 走通用 `accel()` 分支，`inputSign=1`，落点判定、冻结、指标卡全部复用。姿态目标的量程/步长/小数位由 `PLANT_VIEWS` 新增的 `angular / step / decimals / rateSymbol / glyph` 声明。
- **绘制层**：`charts.js` 新增 `paintAttitude()` 与三个机体外形函数（`glyphAircraft / glyphMissile / glyphUav`）。姿态是**绕质心的转动**，所以画成「质心 + 量角器」而不是摆臂，画布与原有三个对象一样保持干净：
  - 质心固定在画布中心（黑点 + 十字），**机体不平移**，绕质心旋转 −θ；
  - 水平虚线 = 零位基准（θ = 0 时机头指向），浅蓝虚线 = 当前姿态轴（虚线，不是箭头）；
  - **画面里只有一支箭头**：棕色弧箭头 = 控制力矩 M，**起点落在蓝色当前姿态虚线上**（随被控物体当前姿态 θ 一起转动），扫向 = 力矩方向（M>0 抬头 / M<0 压头），弧长随 |M| 增长；
  - 弧末端外侧带一个 **M 数值胶囊**（`M=1.02 N·m`，accent 底 + 米白字，与 msd / 倒立摆的力数值标签同一套样式），沿扫向再偏一点，既不压箭头也不压绿线；
  - **目标**：一条**绿色虚线**（从力矩弧起点径向外延伸）+ 量角器内侧的绿色目标标记（短粗线 + 圆点）；量角器刻度圈再外移一档与它错开；
  - 量角器按**角度制**画：每 10° 一小刻度、每 30° 一主刻度并标数字，没有多余的数值读数与说明文字；
  - **飞机、导弹画侧视图**：飞机走「极修长」比例（机身长径比约 11:1，低而后掠的垂尾 + 极薄平尾 + 机腹主翼根部 + 扁座舱盖 + 进气道小口 + 细高光），整体比上一版更纤细；导弹做成**明显比飞机短**的弹体（短粗而非细长）+ 小而后掠的尾翼 + 中段小翼 + 尾喷口。两者都只保留能一眼认出是什么的少数几个特征，不堆装饰；**四旋翼画正视图**（沿机头方向看：左右机臂 + 电机舱 + 近侧实心/远侧半透明的两对旋翼 + 摄像头 + 起落架）。
- **角度单位**：模型内部一律用弧度（`rad`），但**所有面向学生的显示都换算成度**——指标卡（俯仰角/滚转角、误差、RMSE）、响应曲线纵轴、相图横轴、图例、悬停读数、目标与初始偏置滑块都是 `°`；只有角速度保留 `rad/s`（角速度的标准量纲）。实现上由 `PLANT_VIEWS.deg` 标记，`charts.js` 用 `angK = 180/π` 换算数据与刻度，`ui.js` 用 `displayScale` 换算滑块与数值框。
- **教学场景**：新增 6 个预设（`aircraft-pitch-pid`、`aircraft-trim-static`、`missile-openloop`、`missile-pitch-sf`、`uav-roll-p`、`uav-roll-pd`），分别演示静稳定跟踪、静差、开环发散、极点配置镇定、欠阻尼摆动与电子阻尼。

## 5. 公式显示

- 所有控制律与对象方程以**标准 TeX 语法**存储，**优先由本地随包 KaTeX 排版**（`vendor/katex/`，零网络请求）；KaTeX 缺失或解析失败时自动回退：浏览器支持 MathML 时（Chrome 109+ / Firefox / Safari）输出原生 MathML，否则用结构化 HTML 渲染。三条路径都离线可用。
- **重音不再散架**：MathML 路径用 `<mover accent="true">` 把 `˙` / `¨` 压在字母正上方（`θ̈` 紧贴 θ）；HTML 回退路径用 `.m-accent-*` 伪元素绘制。旧实现里希腊字母被误当成运算符、左右各带 0.12em margin，是「重音偏到右上方、θ 与分式之间出现大空隙」的根因，现已按变量渲染。
- **乘号转隐式乘法**：原配置里的 `K_p · e` 在规范化时丢弃 `·`，输出 `K_p e`——这是控制律的标准写法，也避免了点号两侧各 0.12em 造成的松散感。
- **正体命令独立渲染**：`\mathrm{d}`、`\operatorname{sgn}` 走 `.m-rm`（数学字体正体），中文 `\text{}` 仍用无衬线字体，两者不再混用同一类。
- **保留 TeX 显式空格**：`\frac{M l}` 在 MathML 中转为 `<mspace width="0.14em"/>`，分母不再连写成 `Ml`。
- **分式基线**：HTML 回退路径的分式下压量收到 −0.34em，分数线与等号基线基本齐平；MathML 路径由 `<mfrac>` 自动对齐。
- **统一的公式卡片语言**：右栏 `.eq-card`（22px，绿色左边框 + 「控制律 / CONTROL LAW」标签 + 底部说明）、弹窗与文档的 `.eq-surface` / `.doc-math`（29px / 23px），都用白纸底 + 极淡横线纹理 + 左侧绿色书脊，字号比改造前的 15~17px 提升一级。
- **控制律块自适应字号**：先按 CSS 基准字号排版并测宽，超出右栏（320px）时按比例缩小（下限 14px），宁可缩小也不把一条公式折成两行。档案默认折叠时容器宽度为 0，测量会早退，展开后由 `toggle` 事件重新计算，避免字号被钉在下限。
- **公式旁无 TeX / MD 复制按钮**：界面只负责正确、美观地显示公式与变量。文档正文内联公式转为可读 Unicode（`\dot e → ė`、`K_p → Kp`、`s^{3} → s³`），独立公式块仍由 TeX 渲染器排版。
- 导出菜单可导出公式手册 Markdown、CSV 与图表 PNG；教学文档阅读器只做阅读与跳转，不提供任何副本导出（正文唯一来源是 `docs/methods/*.md`）。

## 7. 为什么到达目标后能耗还在增加？

1. **累计能耗 `∫u²dt` 包含稳态保持力**：弹簧负载停在 `x=r` 时仍需 `u_h=k·r≈5 N`，`u²>0` 会线性累加；物理上正确，但把维持代价与调节代价混在一起。
2. 原实现缺陷：波形定格后指标继续累加，造成「曲线不动、数字一直涨」。
3. 定格判定误用固定目标，在正弦/方波下判定错误。

处理：新增**动态能耗 `∫(u−u_h)²dt`** 与**稳态保持力**指标、控制力图橙色保持力参考线；定格后 RMSE 与两种能耗同步冻结并明示「重新录制」；判定改用当前指令 `activeTarget`。

## 13. 滑模抖振与消抖（本轮）

滑模的切换项 `sign(s)` 是抖振根源：切换面 `s` 在滑模面附近来回穿越，指令每步翻转，执行器（电机/阀门）收到的是高频锯齿波。工程上不会直接用裸 `sign`，而是**做平滑**：边界层、连续近似、滤波、二阶滑模、滞环继电器等。

现在 8 个切换型滑模方法（SMC / ISMC / TSMC / FTSMC / ASMC / VSC-RL / ESO-SMC / VariableG-SMC）的切换函数统一走 `chatter()`，参数栏提供 **6 种消抖模式**：

| 模式 | 做法 | 工程含义 | 代价 |
|---|---|---|---|
| `sat`（默认） | 边界层线性饱和 `sat(s/Φ)` | 最经典的边界层滑模 | 边界层内出现微小静差 |
| `tanh` | 双曲正切 `tanh(s/Φ)` | 全局光滑、可导 | 与 sat 同量级，略更平滑 |
| `st` | 超螺旋（√\|s\| 连续项 + 积分项） | 二阶滑模思想 | 幅值降、频率仍高 |
| `lpf` | 对 `sign(s)` 一阶低通 | 状态/测量端滤波 | 引入相位滞后，跟随变慢 |
| `hyst` | 继电器带相对滞环 `(1+Φ)·EMA\|s\|` | 机械冲击保护、降开关频率 | 幅值不降，出现低频极限环 |
| `sign` | 原始硬切换 | 对照基准 | 抖振最大 |

### 两个可量化的抖振指标

指标卡「控制力 u」下方新增副行读数：**纹波 σu · 切换 n/s**。

- **纹波 σu**：控制输入去掉均值后的标准差（0.8 s 滑动窗）——抖振的**幅值**维度；
- **切换 n/s**：开关动作频率（切换面穿越率；滞环模式下统计继电器翻转率）——抖振的**频率**维度。

两者必须一起看：`sat`/`tanh` 降幅值，`lpf`/`hyst` 降频率，`sign` 两者都高。超过 σu > 2 N 或切换 > 20 次/s 时读数转高亮。

### 实测（30 s，Φ=0.1，SMC）

> 下表为 **V5.0 旧口径**（摆平衡辅助以隐藏 PD 写进对象方程）的实测值；V5.1 起辅助改为显式 PI 并与主控制器共用执行器，pendulum 一列的纹波/切换/RMSE 会发生变化，msd 一列不受影响。重跑脚本 `tools/verify-chatter.js` 在 V4.0 目录。

| 模式 | msd：σu(N) / 切换(/s) / RMSE(m) | pendulum：σu(N) / 切换(/s) / RMSE(m)（旧口径） |
|---|---|---|
| `sign` | 10.50 / 50 / 1.2416 | 5.13 / 50 / 0.0287 |
| `sat` | 0.70 / 0 / 2.4667 | 1.14 / 0 / 0.0430 |
| `tanh` | 0.67 / 0 / 2.4667 | 1.14 / 0 / 0.0431 |
| `st` | 3.25 / 48 / 2.3029 | 3.50 / 49 / 0.0375 |
| `lpf` | 2.77 / 13 / 2.4099 | 0.93 / 24 / 0.0445 |
| `hyst` | 10.38 / 12 / 1.2416 | 5.16 / 12 / 0.0130 |

结论：边界层把纹波压掉 **93%**、开关频率压到 0 次/s（代价是边界层静差，RMSE 由 1.24 升到 2.47）；滞环把开关频率压到 **1/4**（50→12 次/s）且**跟踪精度不变**（RMSE 1.2416），代价是幅值仍在。

| 问题 | 现象 | 处理 |

## 14. 小车位置闭环（进阶）

倒立摆是欠驱动系统（2 个自由度、1 个推力），**不能同时任意指定摆角与小车位置**，但可以把两者都镇定到目标：外环负责位置、内环负责摆角。参数栏新增「小车位置闭环（进阶）」分组，默认关闭，仅在倒立摆对象下显示。

### 串级结构

```
x_ref ──► 外环 PD ──► θ_ref（限幅）──► 内环 159 法之一 ──► F ──► 小车 + 摆杆
            ▲                                    │
            └──────── x_c , v_c ◄────────────────┘
```

- 外环：`θ_ref = Kx·(x_ref − x_c) − Kv·v_c`，并限幅到 `±θ_max`；
- 内环：原有 159 条控制律，目标由原来的固定角切换为 `θ_ref`；
- 非最小相位：要让小车右移，必须先向右倾、再靠回正刹车，所以位置响应会先反向一点，属于正常现象。

### 默认参数与验证

| 参数 | 默认 | 说明 |
|---|---|---|
| 位置闭环 | 关闭 | 开启后进入串级模式 |
| 小车目标位置 `x_ref` | 0 m | 范围 ±3 m |
| 外环比例 `Kx` | 0.12 rad/m | 过大易与内环耦合振荡 |
| 外环阻尼 `Kv` | 0.3 rad·s/m | 抑制冲过头 |
| 期望倾角限幅 `θ_max` | 0.10 rad | 限制单次倾斜幅度 |

重新扫描 `Kx/Kv/θ_max` 后取低带宽组合（0.12 / 0.3 / 0.10）：PID / LQR / SMC / TSMC / FTSMC 在 `x_ref = −1 ~ 3 m` 内都能同时锁定位置与摆角。30 s 末段（最后 6 s）实测：PID / LQR / SMC / TSMC 的位置均值误差 < 0.001、位置标准差 0.000、`v_c≈0`、`θ≈0`；FTSMC 标准差 0.016。`x_ref=1.0` 时 PID 终值 0.999 m、SMC 0.99998 m。

为保证「至少两种方法可达成目标」不随迭代退化，V4 期新增两条验收（脚本在 `../历史归档/控制理论模拟器V4.0/tools/`）：

- 静态：`tools/verify.js` 断言默认外环参数为 `0.12 / 0.3 / 0.10`，并实际运行 PID 与 SMC 各 1200 步，要求两者同时满足 `|x_c−x_ref|<0.12` 且 `|θ|<0.12`；
- 浏览器：`tools/verify-file-protocol.js` 在真实页面内同样跑 PID 与 SMC，作为 file:// 验收硬条件。

预设栏新增两个一键复现项：**小车位置闭环 · PID 串级** 与 **小车位置闭环 · SMC 串级**（均自动开启外环、`x_ref=1.0 m`）。参数分组提示也标出推荐内环：SMC / LQR / TSMC / FTSMC / PID。

## 16. 部署到 Netlify（前后端分离）

### 目录约定

```
控制理论模拟器V6.0/
├── netlify.toml        ← 站点配置：publish=public、functions=netlify/functions、安全头
├── public/             ← 前端静态站（Netlify publish 目录）
├── netlify/functions/  ← 后端 Netlify Functions 2.0（顶层文件 + config.path 路由）
├── functions/api/      ← 后端备选：Cloudflare Pages Functions（部署 Cloudflare 时用）
└── tools/              ← 开发期脚本（不发布）
```

| 层 | 目录 | 内容 | 是否必需 |
|---|---|---|---|
| 前端 | `public/` | `index.html` + `styles.css` + `js/` + `vendor/katex/` + `assets/` + `docs/` | **必需**（整站在这里） |
| 后端 | `netlify/functions/` | `chat.js`（智能助手代理）、`health.js`（健康检查）、`share.js`（快照存取，前端默认不调用） | 可选（不部署时助手自动降级本地检索） |
| 构建 | `netlify.toml` | `publish = "public"`、`functions = "netlify/functions"`、缓存与安全头；**不做 `/api/*` rewrite**（与 Functions 2.0 的 `config.path` 冲突） | 必需 |
| 开发 | `tools/` | 校验与生成脚本（不发布） | 不发布 |

### 部署步骤

1. 把**整个项目目录**推到 GitHub / GitLab（Netlify 支持 Git 导入）。
2. Netlify 后台 → **Add new site → Import an existing project**。
3. 构建配置保持与 `netlify.toml` 一致即可（Netlify 会自动读取）：
   - **Build command**：留空（零构建，没有 npm 依赖）
   - **Publish directory**：`public`
   - **Functions directory**：`netlify/functions`
4. Deploy。站点根即 `public/index.html`。

也可以用 CLI：

```bash
npm i -g netlify-cli
netlify deploy --dir=public --functions=netlify/functions
netlify deploy --prod --dir=public --functions=netlify/functions
```

> **不要**用「拖拽 / Deploy manually」只上传 `public/`：那不会打包函数，`/api/chat` 会 404（助手会自动回落直连/本地检索，但同源代理不可用）。

**Cloudflare Pages 备选**：把 `functions/api/` 作为 Pages Functions 目录（按文件路径自动映射 `/api/*`），publish 目录同样为 `public/`；环境变量在 Pages 后台 Settings → Environment variables 配置。两套后端逻辑等价，任选其一，不要同时启用。

### 为什么这样切分

- **前端零依赖、零构建**：`public/` 是一份纯静态站，任何静态托管（Netlify / GitHub Pages / Nginx / OSS）都能直接用；`file://` 双击也照常工作。
- **后端只在需要时存在**：`/api/*` 由 Functions 2.0 的 `export const config = { path: '/api/…' }` 直接声明路由（V4 的 rewrite 写法会与之冲突导致 404，V5 已移除）。前端默认**完全不依赖**后端——不部署 Functions，站点也是 100% 可用的（分享仍走 URL / localStorage，助手降级本地检索）。
- **缓存分层**（`public/_headers`）：`vendor/`（KaTeX）与 `assets/` 版本锁定 → 一年 immutable；`js/` 随发布变 → `must-revalidate`；`docs/` → 1 小时；`/api/*` → no-store。`_headers` 跟着 publish 目录走，换任何静态托管都生效。

### 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/chat` | DeepSeek 同源代理（限流 20 次/分/IP；流式上游超时 55s / 非流式 30s；智能助手调用） |
| `GET` | `/api/health` | 后端健康检查 + 站点自述（版本、159 法 / 12 类 / 11 对象、默认对象） |
| `POST` | `/api/share` | 存入实验快照：`{ data: {...} }` → `{ id }`（上限 64 KB；前端默认不调用） |

```bash
curl https://<your-site>.netlify.app/api/health
```

## 17. 已知限制

- **教学文档的推导是直观推导/设计思路，不是严格数学证明**；控制律为教学演示级离散化实现，参数量级不等价于工程整定值。
- 倒立摆用**在上平衡点线性化**的模型（`sinθ≈θ, cosθ≈1`，且忽略摆杆自身转动惯量 `I_p=0`），仅在 `|θ| ≲ 0.3 rad` 内可信；大角度摆起需要完整非线性模型（本平台不做）。
- 倒立摆仍采用上平衡点线性化，但已维护小车位置/速度状态 `x_c, v_c`，并与摆角联立积分；可视化中的小车位移来自该状态，不再是按 θ 的示意映射。
- 第 3 章闭环极点算例只对能写成**线性定常特征多项式**的方法给出（PID/PI/PD/P 族与极点配置族）；切换、饱和、在线估计类方法改为「为什么算不出解析解」+ 局部线性化框架 + 实验法定增益上限。
- `Linear-Actor-Critic` 在默认参数下数值发散，属该算法在本对象上的固有行为，可减小学习率类参数后重试。
- 三对象聚焦后，一阶惯性 / 直流电机 / Duffing / 液位水箱已移除；需要它们时按 `PLANTS` 的对象定义自行补写绘制函数与条目。
- **30 个「不推荐」组合不是缺陷而是教学事实**：开环/纯比例/线性频域/全状态方法在无回复力或开环不稳定对象上本就无法工作；界面已给出原因与推荐对象，不强行用参数掩盖。
- 对象感知参数覆盖只调整默认值，不改变控制律；覆盖表以外的默认参数保持方法原定义，便于对照。
- 单条轨迹上限 2500 点；稳定 2 秒后自动定格，指标同步冻结。
- 侧栏手动展开**只在本次会话有效**，刷新后按规则回到简略版；`localStorage` 与剪贴板 API 在个别 `file://` 环境受限，已做能力检测降级。
- PNG 导出依赖 `canvas.toBlob`；不支持时会在控制台输出可操作错误信息。
