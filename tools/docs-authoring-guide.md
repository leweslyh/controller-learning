# 教学文档撰写规范（给子智能体 / 作者）

本规范定义「控制理论 99 法」每一份教学文档的**唯一格式契约**。阅读器（`public/js/docs.js`
的 `parseMd`）只认下面这套结构；子智能体**逐法独立撰写**，不要复制粘贴、不要批量套模板，
每一篇都要基于该方法真实的控制理论机理写成面向初学者的讲稿。

---

## 1 · 文件与命名

- 路径：`public/docs/methods/<序号两位>-<方法key>.md`
  - 例：`05-PID.md`、`31-SMC.md`、`99-Feedback-Passivation.md`
- `<序号>` = 该方法在 99 法总列表中的第几位（从 1 开始，两位补零）。
- `<方法key>` 必须与 `public/js/data.js` 中 `CONTROLLER_CONFIGS` 的键**完全一致**。

---

## 2 · Frontmatter（文件头元数据，阅读器读取）

文件**第一行**必须是 `---`，最后一行 `---` 收尾。中间为 `key: value`，
**不要**使用复杂 YAML，本构建脚本只解析简单键值与 `[a, b]` 数组。

```markdown
---
index: 5
key: PID
title: PID控制（比例-积分-微分）
category: "01. 经典线性体系"
plant: 二阶质量-弹簧-阻尼
peers: [P, PI, PD, IPD, 2DOF-PID]
---

（正文从 ## 章节开始写，不要再写 # 大标题，大标题由阅读器用 title 生成）
```

字段说明：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `index` | 是 | 第几讲（整数，两位补零由构建脚本处理，这里写数字即可） |
| `key` | 是 | 方法标识，与 `CONTROLLER_CONFIGS` 键一致 |
| `title` | 是 | 方法中文名（可含英文括号标注） |
| `category` | 是 | 形如 `"01. 经典线性体系"`，与 README 的 11 类一致 |
| `plant` | 否 | 推荐被控对象名（用于「在实验台上动手」提示） |
| `peers` | 否 | 同类可跳转方法 key 数组；缺省时阅读器自动按分类取同类 |

> 一句话简介 `desc`、近似标记 `approx` 仍由 `data.js` 提供，无需在 frontmatter 重复。

---

## 3 · 正文结构（八段式，教学讲稿，口语化、面向初学者）

正文**从 `##` 章节开始**，不要再写 `#` 单级标题（阅读器会用 `title` 生成大标题）。
**固定八段式**，顺序不可调换——尤其**第二节必须先讲被控对象**，不要一上来就推导：

```markdown
## 一、生活里的类比
用日常现象把这个方法「解决什么」讲清楚。比如 PID 像开车：P 看现在离前车多远、I 记
一路上累计的偏差、D 预判距离变化快慢。用类比把抽象符号变成直觉。

## 二、被控对象
先交代「我们到底在控制什么」，再谈控制器。三对象对照 + 主模型 + 符号表 + 特征数字：
- 实验台三个对象：二阶积分器（默认）、质量-弹簧-阻尼、倒立摆；
- 主模型公式（2.1）、状态空间（2.2）、ωn 与 ζ（2.3）；
- 符号表（符号 / 含义 / 默认值 / 范围 / 物理直觉）。

## 三、为什么需要它
讲清楚「没有它会怎样 / 它比上一种方法多解决了什么」。对象讲完，这里正好指出
对象的痛点（例如直流增益 1/k ⇒ 纯比例永远贴不到目标），引出该方法。

## 四、一步步推导
从被控对象方程出发，写出控制律，代回闭环，得到能解释现象的结论。
每一步都配一个公式块（用 `\tag` 编号，章号 = 4），文字解释它「在说什么」。

对象方程：
$$ m\ddot{x}+c\dot{x}+kx=u \tag{4.1} $$

控制律（误差 e=r-x 的现在 / 过去 / 未来）：
$$ u = K_p e + K_i\int e\,\mathrm{d}t - K_d\dot{x} \tag{4.2} $$

代回闭环后得到特征方程，实部决定衰减快慢、虚部决定振荡快慢。

## 五、一个算例（手算 / 直觉估算）
给一组具体参数，算出极点、阻尼比或稳态误差，让「稳定」「超调」变得可数。
表格用 Markdown 表格（见第 5 节）。此节公式用 `\tag{5.x}`。

## 六、参数怎么调（含参数表）
给出本方法在实验台上的可调参数表（参数名、默认、范围、调大 / 调小后果）。
参数名取自实验台实际键名（如 `kp` `ki` `kd`），后果用物理语言，不要主观感受。

## 七、局限与常见陷阱
说清这个方法在什么对象 / 什么工况下会翻车：积分饱和、抖振、模型依赖、噪声放大等。
给初学者「踩坑预警」。

## 八、延伸阅读与同类方法
指向同类或相关的其他方法，用 `method:` 链接（见第 4 节）。一两句话点出演进关系。
```

> 要求：**每节都要有「人话」解释**，不要把推导写成论文。公式是为了支撑直觉，
> 不是为了显得高深。可以写「你可以把这一步理解成……」。
>
> **编号约定**：公式编号的「章」必须等于它所在的小节序号——
> 第二节用 `\tag{2.x}`，第三节 `\tag{3.x}`，第四节 `\tag{4.x}`，第五节 `\tag{5.x}`。
> 篇内编号唯一、连续；正文交叉引用写成「（4.3）」这种全角括号形式。

## 4 · Markdown 子集（阅读器能渲染的写法）

阅读器 `parseMd` 只解析以下子集；其余会原样降级显示，请勿使用复杂语法
（如嵌套表格、HTML 标签、脚注）。

### 4.1 标题
- `## 一、…` 渲染为正式章节（带分隔线与序号）。
- `### 小标题` 渲染为章节内小节。

### 4.2 公式（教材式编号）
- 行内公式用单个 `$…$`，如 `$m\ddot{x}+c\dot{x}+kx=u$`。
- 独立公式用 `$$ … $$`（独占一行，前后留空行）。
- **编号**：在公式末尾加 `\tag{章.序号}`，由 KaTeX 自动右对齐到公式右侧，
  例如：
  ```markdown
  $$ \ddot{e}+2\zeta\omega_n\dot{e}+\omega_n^{2}e=0 \tag{3.3} $$
  ```
  不要手写「（公式 3.3）」之类的文字编号，也不要单独起一行写说明。

### 4.3 提示框（callout）
用引用块 `>` 表示，支持 GitHub 风格告警：

```markdown
> [!NOTE]
> 这是一个普通提示，墨绿软底。

> [!WARNING]
> 这是一个注意，红软底。积分饱和会让超调不降反升。
```

不带 `[!TYPE]` 标签的 `>` 默认按 NOTE（提示）处理。
也可写 `> 注意：` 开头，会自动识别为 WARNING。

### 4.4 列表
- 无序：`- 文本`（支持嵌套用两个空格缩进）。
- 有序：`1. 文本`（渲染为带步骤感的编号列表）。

### 4.5 表格
标准 Markdown 表格，首行表头、第二行分隔：

```markdown
| 参数 | 含义 | 默认 | 范围 / 步长 | 调大 | 调小 |
| --- | --- | --- | --- | --- | --- |
| kp | 比例增益 | 40 | [0,100]/1 | 响应更快但超调上升 | 更平稳但静差变大 |
```

### 4.6 同类方法跳转
用 `method:` 协议链接，渲染为**带下划线的绿色关键字**（不套边框、不加圆角底色），
点击后在阅读器内跳转：

```markdown
- [P控制](method:P) —— 只有比例项，存在静差。
- [PI控制](method:PI) —— 加积分消除静差。
```

### 4.7 行内强调
- `**加粗**`、`*斜体*`、`\`行内代码\`` 均支持。
- 链接到外部用普通 `[文字](https://…)`。

## 5 · 写作清单（提交前自检）

- [ ] frontmatter 字段完整、`key`/`category` 与数据一致。
- [ ] 正文从 `##` 开始，无 `#` 单级标题。
- [ ] **八段式齐全且顺序正确**（尤其第二节「被控对象」必须在推导之前）。
- [ ] 被控对象一节说清：对象是什么、模型方程、符号含义、特征数字。
- [ ] 每个独立公式都有 `\tag{章.序号}`，章号等于所在小节序号，篇内唯一、连续。
- [ ] 至少 3 个生活化 / 直觉化解释，面向初学者而非同行。
- [ ] 含一张参数表（第六节），参数名为实验台实际键名。
- [ ] 「局限与陷阱」非空，给的是可操作的踩坑预警。
- [ ] 文末用 `method:` 链接到至少 2 个同类 / 相关方法。
- [ ] 不出现 HTML 标签、不出现「（见上图）」等无图引用。
- [ ] 全篇中文为主，专有名词首次出现给中文 + 英文。
